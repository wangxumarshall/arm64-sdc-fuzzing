# CORE179 读路径子环节定位战役设计(2026-09-13)

## 一、战役目标与产出定位

把 CORE179 读路径 SDC 从当前分辨率——"L1D 域 load 之后的某处"——细化到具体子环节,四选一(或组合):

1. L1D 数据阵列/way 选择
2. store→load forwarding 网络的字节合并
3. LSU 结果路由(两条 load 的数据错位拼接)
4. 寄存器写回/旁路网络(load 结果与 ALU 结果共用的路由)

**产出边界(预注册)**:本战役产出的是**签名级定位**——哪个环节的签名被复现、哪个被排除;不是最终因果。零扰动的终裁通道仍然是 L1D ECC/RAS(见记忆 intervention-decoupling-impossible-use-pmu 的纪律)。

## 二、取证已裁决了什么(变体往哪打的依据)

### 2.1 内核金标准签名(09-13 crash probe)

样本 1(09-12 10:00 vmcore):期望读 base+160(entry[20]),实际 x20 = base+19..26 处 8 字节。两位置差 141 字节、跨 cache set(128B 翻转 set bit[6])、字节错位 mod-8 = 3。样本 2(09-11 14:31)高半 9226e000 来源未定(候选含前一迭代 add 结果)。

配套实测:崩溃瞬间 `__per_cpu_offset[]` 内存完美健康 → 损坏在 CPU 179 **读侧**,不在内存。

### 2.2 裁决表

| 环节 | 裁决 | 依据 |
|---|---|---|
| L1D way/列选择 | 对内核样本排除 | way 选择只能在同 set 内换线,141B 跨 set |
| TLB 翻译(E8) | 对内核样本排除 | 翻译错是页粒度(4K/16K/64K 对齐)偏移,不是 141B mod-8=3 字节窗 |
| 纯 L2/fill 路径 | 基本排除(有保留) | evict 变体 30min 0-fail(civac+dsb 双变量未净) |
| 纯寄存器堆位翻转 | 排除 | x20 = 某处真实字节的逐字节副本,非翻转后的位 |
| store→load forwarding(E5) | **非必要节点**(降为放大器候选) | ①内核受害者 find_busiest_group 是普通数组读,附近无 store;②NEON store_only 无 reload 仍 14 fail/30min;③最高率骨架 rowmajor 无 E5(temp 从不被 reload);④专门压 E5 的 part_store_fwd_jit/mem_disambiguation 0-fail |
| **幸存嫌疑** | ①AGU 后地址捕获字节级损坏(E6);②LSU 结果路由——两条 load 数据错位拼接;③写回/操作数网络混入 ALU 结果(E3/E4);④forwarding 字节合并(未死透,放大器) | 各自能造出"真字节/错位置" |

注:mrn_flags 纯 ALU 0-fail 与"缺陷在 load 结果递送段"一致。

## 三、方法论:两根支柱

### 3.1 为什么不是 movbe/mrn 时代方法的延续

老变体研究两个结构性死穴(均有翻车记录):

- **布局混淆**:C 代码级变体可能把触发布局改死,触发/不触发分不清是变量还是布局(movbe-l1d-variants-schedule-sensitivity、movbe-multiload-probe-dead-by-scheduling、eigen-ab-split-probe-broken-by-inline 三次翻车)。
- **干预解耦不可能**:改一个变量必然同时改时序,率差只能排除、不能归因(intervention-decoupling 记忆)。

### 3.2 支柱 A:GPS 标签数据

工作集每 8B 字编码:`magic | line_id | intra_offset | generation`(具体位分配见 §6.2)。ALU 结果打轮转 magic。全工作集快照留底。每个 fail 自带来源坐标,自动落入签名桶(§6.1)。

关键性质:**签名分类对率混淆鲁棒**——打标可能改变触发率(Phase 0.5 专测),但改变不了"每个已抓到的事件走了哪条路"。

### 3.3 支柱 B:冻结 asm 骨架

底盘:三轮稳定最高率的 chassis——`neon_rot_ldr_at_top_rowmajor` 族(三轮均值 223 fail/30min,276/244/149;全部 fail 仅 thread 179;见 docs/CORE179_NEON_ROT_LDR_AT_TOP_STABILITY_CAMPAIGN_20260909.md)。

骨架结构(源码实证 tests/cpu/misc/neon_rot_ldr_at_top_rowmajor.cpp:93-120):scratch ldr 在迭代顶(无消费者)→ 2src load(srcA/srcB)→ i%4 轮换 ALU(add/eor/and/orr)→ 背靠背双 str(temp+dst)→ rowmajor 交替扫描(偶轮升序/奇轮降序)→ 冷路径 memcmp。

热循环指令流**字节级冻结**(档位间),所有变体只靠寄存器值/缓冲区初始化切换,objdump 验证同一性。变体差异从"编译期不可控"降到"运行期单变量"。

已知底盘事实:骨架效应(标量族内部 5.6×:agu_stress 0.63→mrn_reloaded 3.5/min)大于通路效应(NEON vs 标量 1.4-1.7×),这是支柱 B 必须冻结骨架的原因。

## 四、转发边覆盖矩阵(把流水线转发当作网络管理)

每个变体显式声明经过的递送边,交叉对比只在"边集差异即所问问题"的变体对之间做。

| 边 | 路径 | 在冠军骨架中 | 故障签名 | 状态 |
|---|---|---|---|---|
| E1 | ldr(srcA)→vALU 操作数,0 拍 | 有 | 两源拼接/错位窗 | 嫌疑 |
| E2 | ldr(srcB)→同一 vALU 另一操作数,0 拍 | 有 | 两源拼接/错位窗 | 嫌疑 |
| E3 | vALU 结果→str 的 store data,0 拍 | 有(×2) | ALU 混入 | 嫌疑(K4b 旋钮) |
| E4 | ldr(scratch)→无消费者,只走写回 | 有 | ALU 混入/错位窗 | 嫌疑 |
| E5 | store→load forwarding | **无**(temp 不被 reload) | 陈旧代 | 放大器候选(非必要已证) |
| E6 | 地址计算→AGU→L1D 访问 | 有 | 错线/错位窗 | **嫌疑**(K5 判别对象) |
| E7 | L1D way 选择→数据读出 | 有 | 错线/错字 | 内核样本已排除;用户态 K3 复核 |

**证据重排后的中心假设(假设,非结论)**:唯一兼容全部样本的节点收窄到"load 结果递送段"——E1/E2(load→use bypass)+ LSU→写回路由。lane 绑定(§5 K7)在转发视角下的自然解释:向量侧 bypass/结果路由按 lane 组织,若缺陷在 64b lane 组织的那段物理路径,则 2×64b 触发、4×32b/16×8b 归零、标量(原生 64b)也触发,一个假设全覆盖。

## 五、变体矩阵(旋钮)

| 旋钮 | 档位 | 裁决什么 | 证伪判据 |
|---|---|---|---|
| **P0 标量底盘** | rowmajor 骨架标量 64b 版(asm `ldr "=r"`) | 最高率骨架的 NEON-vs-标量差(空白);若标量底盘高率,与内核金标(标量 load)对接更直接 | — |

| ALU 轮换 | on/off | 已知必要(纯单指令 36min 全 0);新测:错误类别是否随轮换变化 | — |

OoO 语义诚实化:乱序核上"指令间距"是软控制——间距大只是关掉 bypass 窗口(迫使走寄存器堆),不确定性指定机制。两极(0 拍/超窗口)机制干净,中间档是混合。旧数据已证这条轴强非单调(mrn_rmw nop 0/1/2/64 = 18/1/6/0;probex back-to-back 非单调),非单调形态本身是信息。

**K7 的既证事实(为什么 load 目的寄存器类不是变量)**:三档 NEON 变体(2×64b/4×32b/16×8b)用**同一条 `ldr q`、同一个 NEON 寄存器堆**(源码实证:load_vec 同一 asm `"ldr %q0,[%1]" : "=w"`,neon_rot_2src.cpp:45 / neon_rot_u32x4.cpp:45),唯一差异是 ALU 指令 lane 形状(`add v0.2d/.4s/.16b`),且三档全部带同构 i%4 轮换(add/eor/and/orr)。结果:2×64b=26-33、4×32b=0(1651 loop exit:pass)、16×8b=2。若高危点是"load 写入 SIMD 寄存器堆",三档应同高——直接证伪;若在"load 写入 GP 堆",标量族不该 fail(19 fail)——也证伪。**绑定点在"按什么 lane 粒度组织/消费数据"这一层**(ALU 执行级、lane 路由级、或 pattern 层,三者源码层分不开,正是 K7 要拆的)。

干净配对数字(唯一可干净配对的是 2src 家族,同 30min 全核 192+auto seed、同口径唯一 fail 块):

| 数据通路(2src 配方) | fail/30min | vs 标量基准 19 |
|---|---|---|
| 标量 64b(agu_stress_2src 基准) | 19 | — |
| NEON 2×64b(add v0.2d) | 26-33 | 高 1.4-1.7× |
| NEON 4×32b(add v0.4s) | 0 | 低 19+× |
| NEON 16×8b(add v0.16b) | 2 | 低 ~10× |

不干净数字(不计入配对):store_only NEON 14 vs 标量 1(标量 n=1+依赖链/AGU 混淆已撤回归因);ldr_at_top rowmajor NEON 223(全项目最高)但标量版从未跑过(=P0 要补)。

## 六、GPS 标签与签名分类

### 6.1 签名桶(9 桶)

| 桶 | 签名 | 指向(候选,非定罪) |
|---|---|---|
| 错线 | 拿到别的 cache line 的真字节 | L1D/地址侧选择 |
| 错字 | 同线内错 8B 字 | 线内选择/对齐 |
| 错位窗 | 字节错位 mod-8 直方图非零 | 字节拼接/steering |
| 陈旧代 | 拿到旧 generation | missed forward(依赖 store 时) |
| 两源拼接 | 一个 8B 值里同时含 A 标和 B 标字节 | **LSU 结果路由实锤** |
| ALU 混入 | 含轮转 magic 的 ALU 结果 | 操作数/结果网络(E3/E4) |
| **部分字**(新增) | 8B 内仅部分字节错(1B/2B/4B 粒度直方图) | 半字级合并错误 |
| **位翻转**(新增) | 不可寻回且低汉明(翻转位数/位置直方图) | 真位翻转 vs 错位读伪影(§9.2 判别) |
| 未分类 | 离线全快照检索兜底 | 在途/生成中数据(bypass/ALU 方向的强约束) |

"全部未分类"≠失败:它指向 fail 值不来自工作集任何位置 ⇒ 在途数据,即 bypass/ALU 混入方向(前提:离线快照检索先被验证可用)。

### 6.2 GPS 编码格式

每 8B 字:`magic(16b) | line_id | intra_offset | generation`,具体位宽分配实现期定(约束:line_id 能索引 1024 entry 缓冲;intra_offset 字节粒度;generation 每 TEST_LOOP 迭代轮转)。ALU 结果打轮转 magic(与操作数区分)。两源互补标签:srcA=AAAA 系 magic、srcB=BBBB 系 magic(K5 判别用)。

### 6.3 桶与机制的排除矩阵(签名分布只排出嫌疑名单,排除实验定罪)

| 签名桶 | 候选机制 | 排除/判别实验 |
|---|---|---|
| 错位窗/错线 | E6 地址捕获损坏 vs 数据 steering | **K5 远隔双源**:fail 是连续 8B 真窗 → E6(地址错,取到的错位置数据本身完好);fail 是 A+B 拼接字节 → steering |
| 陈旧代 | forwarding 漏发 vs 其他陈旧源 | **K2 无 store 纯 load 格**:陈旧代桶消失 → 依赖 store;存活 → 陈旧另有来源 |
| 两源拼接 | LSU 结果路由 vs 写回端口争用 | **K4 间距梯度**:拼接率随间距单调变化 → 路由/端口类;不变 → 另找 |
| ALU 混入 | E3(ALU→store data)vs E4/写回 | **K4b ALU→str 间距梯度** |
| 位翻转样 | 真位翻转 vs 相似数据错位读伪影 | **Phase 0.5 双轨**(§9.2,白送的判别) |

### 6.4 独立验证通道(防自证)

1. **阶段 1 协议即框架假阳性检验**:排除 179 跑 191 核要求 0 fail——golden 算错/memcmp bug 会在其他 191 核同样 fail(九轮战役 0 例)。
2. **每个被分类的 fail,golden 复算在非 179 核上完成**(isolated-recross-golden 协议,不碰热路径)。
3. **RAS/L1D ECC 计数器并行读**:战役期间持续;探针报故障而 ECC 不动本身是数据(与终裁通道同一资源,提前接入)。
4. (可选,降级)VIXL 第三方重算 golden——与 191 核复算冗余,非必选。
5. 已排除:"另一台机器复现"——179 是本机独有硅缺陷,第二台健康机只能验框架(已被 1 覆盖),验不了机制。

## 七、K5 决定性格设计(全场最重要)

两源远隔(不同线不同 set)+ 互补标签(srcA=AAAA 系、srcB=BBBB 系)。邻近双源时拼接与错位窗的字节完全相同(不可区分),**远隔才让"拼接"暴露出跨线字节混合**。

- 一个 fail 里同时含 A 字节和 B 字节 = 两条 load 结果拼接实锤 → fault 定位到 LSU 结果路由/steering(内核样本 1 签名在用户态复现)
- fail 是单线连续 8B 窗 = 地址/数据选择级(E6)

## 八、K7 pattern 电池(收窄 lane 绑定)

要判别的真问题:**4×32b 的 0 是"非 64b 物理通路"还是"32b 运算的结果 pattern 恰好不激活"**。

1. 固定 2×64b,跑 pattern 电池(全 0/全 1/随机/高汉明/低汉明)→ 映射 64b 通路的激活面;
2. 同一电池跑 4×32b:若所有 pattern 下 2d≫4s,pattern 解释需要跨全部 pattern 的完美反相关——可能性低但非零,只能收窄不能定罪。

已知限制:eor 是 lane 不变的(eor .2d 与 .16b 位级同结果,大概率同物理异或网络),帮不上忙;真有物理差异的是 add 族进位链(16 条独立 8b 进位链 vs 2 条 64b)。此实验排 P4。

注:pattern 依赖已是确证事实(特定 bit pattern 落在缺陷位置才暴露),所以"率随位模式变→数据路径问题;不变→lane 问题"的推理不成立——率当然随位模式变。电池测的是 32b/64b 的**相对**激活面差异,不是绝对率。

## 九、Phase 0.5 双轨设计(标签敏感度 + eigen 伪影判别,一份数据两用)

### 9.1 背景

打标改变的是数据位模式,而 pattern 依赖是已证事实——标签可能激活**不同的故障路径**,不只是改率。

### 9.2 设计

- **A 轨**:自然随机数据(memset_random)同骨架;
- **B 轨**:GPS 打标数据(= champion+打标,兼"全能格"签名多样性种子+聚类检验);
- 各跑相同时长(全核 192 含 179 + auto seed);
- **比较签名分布,不只比较率**。A 轨无 GPS,可比的是粗分类:①fail 值能否在全工作集快照中寻回(可寻回=真字节错位)②与期望值的汉明距离分布 ③出错字节粒度直方图。细桶只有 B 轨有。卡方检验在粗分类上做。

### 9.3 白送的判别(可能是 0.5 阶段最大价值)

既有事实:用户态三家族三种签名——eigen 尾数主导 1-2bit"翻转"(eigen-sdc-bitflip-position-stats)、movbe 14-21bit 多位翻转、内核金标真字节错位窗。**若 A 轨出现 eigen 式低汉明"翻转"、B 轨同量级 fail 里大量是"可寻回真字节",则 eigen 的尾数翻转统计被证伪为错位读伪影**(邻元素共享符号、只在尾数差异——错位读在相似数据上看起来就像尾数翻转)——用户态与内核态 manifestation 统一。反之若 B 轨也大量出现真位翻转,则两种形态并存,多缺陷假设(§10)获得直接支持。

### 9.4 通过/失败判据

- A vs B 粗分类分布一致(卡方 p>0.05)→ 标签对路径无影响,GPS 可放心用于正式格;
- 分布不一致 → 标签改变了故障路径,GPS 方案重新设计(此为 0.5 阶段的否决权)。

## 十、多缺陷/条件性缺陷检验

"多缺陷"不是防御性假设,是已登记的可能性:内核 09-04 22:09 dump(CPU 50 list 损坏+同秒 180 WARNING)已被记录为 freeze 时代第二种多核/写侧模式,与 179 读侧是两种形态。

- **聚类分析**:对 0.5 B 轨(≈全能格)的签名做聚类/多峰检验——多峰提示多缺陷点,单峰支持单缺陷多签名;
- **温度/频率扫描降级为"每格记录+交错基线"**:温度轴是独立战役体量(记忆 temp-sdc-correlation-monitor:只能干预实验回答),塞进定位战役会把两者都做脏。扫描另立项;
- 每格记录 IPMI socket 级温度(45-96°C 通道已有);尝试 cpupower 锁频,服务器平台大概率锁死,不可用则记录让步。

## 十一、预注册判据与统计功效

### 11.1 成功判据

- **主判据**:决定性格(如 K5)中某签名桶占比 vs 交错标准格,Fisher 精确检验 p<0.01,双侧各 ≥100 个已分类样本;
- **次判据**:≥2 个不同旋钮的格产生指向同一条边的签名偏移;
- **"全部未分类"**:按 §6.1 解释为在途数据指向,不算失败(前提:离线快照检索已验证可用);
- **低功效预承诺**:<50 个已分类样本的格只报告 suggestive,**禁止**下"无差异"结论。

### 11.2 功效数字

- 占比差 30% vs 50%(中等效应):n≈93/侧 → **取 100**;
- 占比差 30% vs 40%:n≈355/侧——只有 champion 率(223/30min,约 15-20min 攒够 100)的格负担得起;
- **结论:>10 点的占比差才可判,<10 点只做提示**;
- 低率格排程:去 store 后可能掉到 ~0.6/min,100 个样本需 ~3h,按此给时长。

### 11.3 交错标准格(基线漂移检测)

已登记未解释漂移:rowmajor 逐轮走低 276→244→149(sub 平稳)——非稳态是事实,格间率比较不可靠,签名分布是否更稳待验。

- 每 2-3 个实验格插一个标准格(champion 配置不打标);
- 标准格同时跟踪率+签名分布——若签名分布也漂移,格间比较需校正;若稳定,证明签名分布对时间鲁棒(本身是重要结论)。
