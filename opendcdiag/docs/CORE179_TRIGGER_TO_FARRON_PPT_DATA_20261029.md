# 从触发序列到 FARRON：SDC 检测的完整故事线（PPT 素材，自包含版）

**日期**：2026-10-29　**叙事轴**：什么指令序列触发 SDC → 什么负载类型容易触发 → **温度如何调制出错频率** → 最强检测器多快 → 用例分级 → FARRON 如何快速高效锁定故障核（每步配实测数据）
**数据来源**：两个月触发配方战役 + 三形态 FARRON 验证（全部可溯源，见 §九）

## 一、一页速览（故事线五步）

1. **指令层**：发现触发 SDC 的指令序列配方——**3 次内存读取 → 轮换运算 → 背靠背双写回**，三要素缺一不可
2. **负载层**：容易触发的是**NEON 向量"读-算-写"型负载**，且要求**整插槽并发独占**——共享/单核/换负载类型都会让错误消失
3. **调制层**：出错频率被**本座温度**单调调制——**52°C 约 13 次/分 → 64°C 约 1.8 次/分（每 +3.5°C 减半，全程 ~7×）**；频率、电压两轴均被排除
4. **速度层**：最强检测器 `neon_rot_ldr_at_top_rowmajor`——**30 秒窗口 100% 必中**，窗内首错中位 17 秒，最快 3.6 秒
5. **系统层**：57 个用例按触发率分五梯队入池，FARRON 每 30 分钟用 2 分钟扫完全机——**应用损失 1.815%、自身消耗 0.88%、零误报、定位到核**

## 二、指令层：什么指令序列容易触发 SDC（多核负载环境下）

### 2.1 触发配方（两个月对照实验的结论）

每个线程反复执行的核心序列（1024 个数据槽循环扫描）：

```
ldr  scratch[i]        ← 第 3 次读取（弃用，撑开时序）
ldr  srcA[i]           ← 源操作数 A
ldr  srcB[i]           ← 源操作数 B        ← 三要素①：≥2 个源 load
add / eor / and / orr  ← 按 i%4 轮换        ← 三要素②：轮换 ALU
str  temp[i]           ← 写回
str  dst[i]            ← 背靠背第二个写回   ← 三要素③：紧时序（str→ldr ≤2 周期窗口）
（每扫完一遍：与预计算的标准答案逐字节比对 16KB）
```

**本质**：179 号核的 L1D 读路径以约 **百万分之一每次读取** 的概率随机错一位——配方的作用是让被测核以最大密度"踩"这条读路径（单核每窗 ~77 万次读命中）。

### 2.2 三要素的对照实验证据（缺一即零检出）

| 灭活对照（改动一处） | 结果 | 证明的必要条件 |
|---|---|---|
| 减到 1 个源 load | **0 触发** | ≥2 源 load 必要（梯度：2源14 / 3源10 / 4源4） |
| 单一运算不轮换 | **0 触发**（36min） | ALU 轮换必要 |
| 插入 ≥8 周期 nop 拉开时序 | **0 触发** | 紧时序必要（str→ldr ≤2 周期窗口） |
| 去掉 store | **0 触发** | 背靠背 store 必要 |
| 64 位 lane 改 8 位 lane（u8x16） | 触发率塌缩 15× | 64b lane 组织是关键 |
| 走 L2（逐出 L1D） | **0 触发** | 必须 L1D 命中/转发路径 |
| 改成标量 64b 直译 | **0 触发** | 触发绑定 NEON 向量组织 |
| 逐字节比对改宽松比对 | 漏检 | 全量 memcmp 必要 |

## 三、负载层：什么类型的负载容易触发

### 3.1 负载画像

**容易触发**：NEON 向量"读-算-写"循环、双源、运算轮换、背靠回写、L1D 命中、满占被测插槽。
**不触发**：纯 ALU、纯 store、单源、松时序、标量、L2 路径、共享插槽的分时负载。

### 3.2 两条环境铁律（多核负载环境的关键发现）

**铁律一：整插槽独占**（三构型对照实验，同样满载背景）：

| 方案 | 检出 | 说明 |
|---|---|---|
| 单核独占测试 | 330s **0 检出** | 并发条件不满足，错误不显形 |
| 测试与业务共享插槽 | 2×30s **0 检出** | 时序配方被并发负载打散 |
| **整插槽独占测试** | **每窗必检出** | ✅ 唯一有效形态 |

**铁律二：背景负载类型门控**（热震荡战役，等温对照）：同样的温度、同样的探针——movbe 背景 30 分钟 **0 次**，neon 背景 30 分钟 **47 次**（二项 p≈10⁻¹⁴）。触发严格跟随背景负载类型切换（切换后 1-100 秒内响应）。

**并发规模**：插槽自足——48 核插槽级满载的触发率（14.9/min）与全机 168 核满载（15.4/min）持平，不需要全机压力。

## 四、调制层：温度—SDC 频率规律（深层机理发现）

负载恒定、只调风扇变温（两个独立战役交叉验证）——179 的出错频率随**其所在插槽（CPU4）的温度**单调下降：

| CPU4°C | 52-53 | 55.5 | 56.7 | 57.2 | 61.7 | 63.4 | 63.9 |
|---|---|---|---|---|---|---|---|
| 频率（次/min） | **13.0-15.6** | 9.4 | 7.7 | 5.8 | **2.8** | **2.1** | **1.8** |

**规律：约每 +3.5°C 频率减半，52→64°C 全程 ~7×。**

### 4.1 定案证据（CPU4-only 五窗对照，负载 12.8h 不停）

- **同为 53°C 的两窗**（深夜 vs 清晨，相隔 8.3 小时）：频率 12.96 vs 13.17——**仅差 1.6%**
- **相邻 27 分钟窗**随降温即刻翻转：63.4°C 的 2.10 → 53.0°C 的 12.96
- **520 分钟稳定热基线**（63.9°C，1.78/min）后风扇恢复，1 分钟内温度回落、频率随即跳回 13+
- → 排除"179 自身活跃周期恰好撞上温度变化"的替代解释；吞吐全程平坦排除降频伪影

### 4.2 三轴判决（什么在调制 SDC）

| 轴 | 判决 | 证据 |
|---|---|---|
| 频率 | 无关 | PROCHOT 降频期（时钟近停摆）率 1.07 vs 0.99/min 不变 |
| 供电电压 | 无关 | 2026-10-29 直接测量：73 个 SDC 时刻主核轨恒 0.96V、电压分布与负载期重合 |
| **本座温度** | **强因果** | 每 +3.5°C 减半，单调、可重复、跨战役一致 |

（残留未分离项：温度 vs 风扇振动/气流——所有变温均经风扇实现，对照臂实验待跑；µs 级电压瞬态不可测。）

### 4.3 对 FARRON 的设计含义

- **热端检出概率会降**：63.9°C 时频率 1.78/min → 30s 窗期望 0.9 次 → 单窗约 59%——**热态插槽需要加长窗口**（FARRON 设计已含温度自适应时长档 60/120/300s，正好覆盖）
- 生产实测窗温 53-58°C（频率 3.5-5/min）→ 30s 窗保持 100%
- 机理候选：时序裕量——**冷硅路径更快 → 读路径转发窗口更紧 → 错误更多**——与触发配方对时序的极端敏感性（§2.2 的 nop≥8 灭活）自洽

## 五、速度层：最成功的 neon 多快找到 SDC

**主力检测器 `neon_rot_ldr_at_top_rowmajor`**（57 个活跃用例中触发率第一，全史最高稳态）：

| 速度指标 | 实测值 | 来源 |
|---|---|---|
| **触发率（暴露期）** | 8.5/min（全核七轮均值）～ **15.4/min**（168 核，史上最高持续） | 多战役 |
| **30s 窗口检出率** | **100%**（147/147、87/87、12/12 三役复验） | 5h/3h/6h |
| **窗内首错时间** | 最快 **3.6s**；中位 **15.9-17.3s**；p90 36s | 三役分布 |
| **端到端首检**（系统启动→锁定缺陷核） | **118-128 秒** | 三役 |
| 窗口下限 | 15s 窗仅 35-42% 检出——**30s 是可靠性底线** | 5h/6h |

**为什么这么快**：30s 窗内单核约 **250 次全量比对、~77 万次读路径命中**；179 暴露期出错率 3.5-15/min，30s 期望 1.7-7.5 次命中——概率上窗窗必中。

## 六、分级层：测试用例梯队（分级后 FARRON 才能高效）

全部 148 个候选用例经两个月战役洗礼，分为：

| 梯队 | 数量 | 触发率 | 代表 |
|---|---|---|---|
| **P0** | 6 | **≥3/min** | neon_rot_ldr_at_top_rowmajor（~8.5）、sub（3.9）、mrn_reloaded_2src_alu（3.5）、str3（3.3）、movbe（3.0）、mla（3.0） |
| P1 | 5 | 2-3/min | rowmajor_gps（2.9，取证用）、k7p_rand 等 |
| P2 | 11 | 1-2/min | K-cells 家族、movbe_l1d 等 |
| P3 | 15 | 0.1-1/min | 机制对照/梯度用例 |
| P4 | 20 | <0.1 或间歇 | 条件级 |
| 基础级 | 83 | **0（灭活对照）** | 每条证明一个必要条件（§2.2 的证据来源） |
| 排除 | 8 | — | 会死机的原版（禁跑）、多核风暴等非 179 源 |

**分级的价值**：P0 = 日常检测主力（快）；P1-P2 = 诊断与签名采集；基础级 = 配方边界的存证——**梯队的每一层都有战役数据背书**（率有跨夜 0.45×~4× 波动，同晚排序才严格）。

## 七、系统层：FARRON 如何用分级用例快速、高效锁定故障核

### 7.1 调度逻辑

- **选题优先级**：可疑级（该核上新发现错误的用例）> 活跃级（P0→P4 轮换）> 基础级
- **生产节奏**：每 30 分钟一轮，一轮 = 4 颗 CPU 各 30s 窗背靠背 = **2 分钟扫完全机 192 核**
- 每窗七步：业务整插槽迁出（搬不是停）→ 48 线程钉核跑检测器 → 数错 → 证据存档 → 业务迁回 → 记账
- 检出即三要素落盘：**哪个核、第几秒、什么种子**——一次事件完整可追溯

### 7.2 "快速"的数据支撑

| 主张 | 数据 |
|---|---|
| 窗内极快 | 首错最快 **3.6s**，中位 **17.3s**（≤30s 占 75%，100% 最终检出） |
| 全机一轮极快 | **2 分钟**扫完 192 核（30s × 4 插槽） |
| 端到端极快 | 系统启动到锁定缺陷核 **124 秒** |
| 每轮必中 | **246/246** 个缺陷插槽窗全检出（147+87+12，三役复验） |
| 反衬设计必要性 | 单核探针 330s 零检出、分时方案 2×30s 零检出——**快是"整插槽独占+30s 窗"设计买来的** |

### 7.3 "高效"的数据支撑

| 主张 | 数据 |
|---|---|
| 业务代价极低 | 应用吞吐损失 **1.815%**（每核被占 30s/30min=1.67% 机会成本 + 0.12% 监控本底） |
| 自身消耗极低 | FARRON 仅占全机 CPU **0.88%**（≈1.67 核当量） |
| 零误报 | **741 个干净插座窗零误报**（441+264+36，三役） |
| 定位精确 | 100% 锁定到逻辑核号（三法交叉：cpu-mask/线程号/记账列） |
| 证据完整 | 每次检出留 fail 块（核号/秒数/种子），可复现可审计 |
| 检测与业务解耦 | 业务零崩溃零重启（6h 实测），检出率与扫描频率无关（连续扫与 30min 节奏同为 100%，代价差 13×） |
