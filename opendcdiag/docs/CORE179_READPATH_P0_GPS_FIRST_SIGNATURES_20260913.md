# CORE179 读路径定位战役 P0/P0′ 首轮结果(2026-09-13)

配套:`docs/CORE179_READPATH_LOCALIZATION_CAMPAIGN_20260913.md`(设计)、`docs/CORE179_READPATH_P0_IMPLEMENTATION_20260913.md`(实现记录)。本文记录 2026-09-13 傍晚首轮 30min 战役的实测结果与签名分析。数据文件:`builddir/campaign_p0/`(两份 log)+ `movbe_log/gps_rowmajor/`(87 个 dump,每 80KiB)。

## 一、总结果

| 格 | 条件 | 时长 | 结果 |
|---|---|---|---|
| P0 标量 64b 底盘 | 全核 192 含 179,auto seed | 30min | **0 fail**(1610 迭代全 pass,三法交叉:exit:pass + 0 result:fail + 0 miscompare) |
| 阶段 1 框架检验(双测试) | 179 hotplug 下线,191 核 | 60s | 54 pass / 0 fail / 0 误报 dump |
| P0′ GPS B 轨 | 全核 192 含 179,auto seed | 30min | **87 fail,全部 thread 179**;87 个 dump 1:1 落盘 |

**P0 结论(空白填补,预注册判据口径)**:最高率 NEON 骨架(rowmajor,三轮均值 223/30min)的标量 64b 直译版在同等条件下 **0 fail**。标量版迭代率反而高 4×(1117ms vs 4521ms/迭代,同 16KiB 数据量/迭代),不是"跑得少"。**触发绑定在 NEON/向量递送路径上,标量 64b 路径(原生 64b lane)在该骨架下干净**——lane 绑定(K7 轴)的首个数据点:与 2×64b(触发)/4×32b(零)并列,标量 64b 归零,四点曲线为 标量64b=0 / 2×64b=223 / 4×32b=0 / 16×8b=2。这不是"64b 物理通路"简单假设能解释的(标量也是 64b!)——**绑定在 NEON 寄存器文件/lane 组织的消费侧,且需要 2×64b 的 SIMD 组织**。

**P0′ 结论**:GPS 打标版 87 fail/30min(约 2.9/min,较父版 223/30min 低约 2.6×,符合"打标改变位模式→率变化"预期,Phase 0.5 的 A 轨对照即父版既有数据)。全部 fail 在 179。**离线快照检索通道验证可用**(前提达成),产出下述签名族谱。

## 二、签名族谱(87 dump / 178 出错字)

### 2.1 主族:同缓冲字段替换(78 dump,156 字,93%)

签名:出错字 `got` 的 **off|~off 字段(byte 2-5)被替换为 srcA 另一字 `A[j]` 的同字段**,其余字段(gen 低 16b、magic 高 16b)保持正确;**off 与 ~off 的互补校验在替换后依然通过**(替换源本身是合法标签字)。

字节粒度细分:

| errbyte 模式 | 数量 | 含义 |
|---|---|---|
| [2,3,4,5] | 106 | 32b off\|~off 字段整体来自 A[j] |
| [2,4] | 40 | off 的 LSB + ~off 的 LSB **成对**来自 A[j](40/40 验证:两字节来自同一 A[j]) |
| [3,5] | 8 | off 的 MSB + ~off 的 MSB 成对来自 A[j] |
| [2..7] | 2 | off\|~off\|gen 六字节来自 A[j] |

关键统计:

- **替换源 100% 在 srcA**(156/156;srcB/scratch 零命中)——不是两源拼接,是**同缓冲跨字替换**;
- 元素距离(j−idx)全直方图:−28…+12,**全部为偶数元素距离(8B 对齐)**,主峰 −12(64)/−8(38)/+8(14)/+12(14)——即 ±96B/±64B/±64B/±96B,**±1 到 ±3.5 条 cache line 的近邻**;
- lane 分布 78:78 完全均衡(uint64x2 两 lane 无偏好);
- op 分布(i%4):**orr=110(71%)、and=36(23%)、eor=8、add=2** —— 强 op 偏置(见 §四讨论)。

### 2.2 头部族:错位窗 + 不可解码(9 dump,22 字)

fail 集中在 word 0-2(缓冲头部)的 dump,两类:

- **mod-8=1 字节错位窗**(2 dump):`got` 的高 4 字节 = srcA 字节流 byte10593/3361 处的**错位 1 字节连续窗**(如 `A[1324]` 的 bytes[1..5]),来源字距 fail 字 420-1324 元素——远距错位读。**这是内核金标签名(x20 = mod-8 错位字节窗)在用户态的直接复现**,首次把两种 manifestation 桥接。
- **全零/无窗**(7 dump):`got[0]=0x0`、或含未解码字节(0x29/0x0d 注入 gen 字段、0xff5e/0x81a1 等),无法在工作集寻回——指向在途/生成中数据(bypass 方向,与设计文档 §6.1 "unknown 桶"解读一致)。

## 三、框架机制勘误(影响后续所有 dump 命名)

实测确认(探针 probe_cpu_param + 源码追溯):

1. **框架按 NUMA 域切片 fork**:默认 `--reschedule` 相关配置下,Heuristic 切片把 192 核切成 8 个 NUMA 域 child(各 24 线程);每次 fracture/retest 迭代重新 fork(4s 探针产生 3680 个短命 child)。
2. **`test_run` 的 `cpu` 形参 = child 内线程号(0..23),不是逻辑核号**。child 内 `device_info` 被 `restrict_topology()` 偏移到 slice 起点,故 `fail_cpu11` = 7 号 child(覆盖 168-191)的 11 号线程 = **逻辑核 179**。与框架日志 `thread: 179 / logical: 179` 及 cpu-mask 第 179 位 X 三方互证——**87 个 dump 全部由逻辑 179 上的线程写出**。
3. dump 文件名中的 sweep 号是 child 内局部计数器(各 child 独立),不影响离线分类(每文件独立解析)。

工程含义:后续任何 dump 命名若要直接可读,应使用 `sched_getcpu()` 而非 `cpu` 形参;本轮数据已经三方互证无需重跑。

## 四、解读(候选,非定罪——按排除矩阵走后续)

1. **主族不是位翻转**:"2-bit 翻转且恰好保持互补结构"需要两个独立 bit 完美协同;而 40/40 的 [2,4] 模式字节对来自同一 A[j]、156/156 替换源全在 srcA 且全 8B 对齐——**结构性替换,不是随机位损伤**。eigen 时代"尾数主导 1-2bit 翻转"统计(位翻转桶)在本底盘不成立,支持 §9.3 的"错位/替换伪影"判别方向。
2. **主族不是 E6(地址捕获)**:地址错(E6)会取到**错位置的完整真字节**(错线/错位窗桶);主族拿到的是**正确位置的字段被近邻字段的对应字段覆盖**——A[j] 的 off|~off 并非通过 load A[j] 的地址错误到达(那样会整词替换,见头部族的错位窗),而是**字段对齐的部分替换**。
3. **主族候选:同缓冲近邻字段的递送串扰**——A[j] 与 A[idx] 相距 ±1-3.5 line,出错字段恰好是 32b 中段(off|~off),与 64b 数据通路的**字节使能粒度(2B/4B)窗口**吻合。物理候选:LSU→寄存器堆写回的字段级串扰、或 store data(E3 边,temp/dst 双写)与 load 数据在写回端口的字段碰撞。**这正是 K4b(ALU→str 间距)与 K4(消费间距)要拆的**。
4. **头部族的 mod-8=1 错位窗与内核金标同构**——E6/steering 的判别(K5)在用户态有了锚点:错位窗=真字节错位读,与主族的字段替换是**两种不同签名**,若 K5 后仍并存,支持"多签名单缺陷"(§十聚类)而非多缺陷。
5. **op 偏置(orr 71%)与 pattern 依赖一致**:orr 的 magic 段=a5a5|5a5a=0xffff(全 1 段),and=0x0000(全 0 段)——出错字段集中在 off|~off 段(数据多样性段),magic/gen 段(全 0/全 1)几乎不损伤([2..7] 仅 2 例)。**损伤不是均匀随机的,避开全 0/全 1 字节段**——与"特定 bit pattern 落在缺陷位置才暴露"一致,提示物理层是**数据相关(pattern-sensitive)的近邻耦合**,而非纯时序。

## 五、与旧数据的矛盾了结

- **store_only(NEON 14/30min)vs fwd_probe(0)旧矛盾**:本轮 GPS 版保留双 str(temp+dst)且 temp 从不被 reload,fail 照常发生——**store→load forwarding 不是必要条件**(与内核侧 find_busiest_group 无 store 的旁证一致),K2 轴的判决方向已提前获得一个强数据点。
- **NEON vs 标量**:同骨架标量版 0 fail,把"load 写入 GP 堆即触发"的假设进一步收窄(此前标量族 19 fail 来自 2src 家族的不同骨架,非本骨架)。

## 六、下一步(按设计文档优先级序更新)

1. **K5 远隔双源**(P1,决定性格):现编码已支持(A/B 互补 magic)。主族"源 100% 在 srcA"提示:当两源远隔时,若替换源仍全在 srcA → 串扰与源缓冲身份相关(近邻物理位置);若开始出现 B 字段 → 路由无差别。头部族错位窗的远距源(420-1324 元素)已有先例。
2. **K4/K4b 间距梯度**(P3):拆"字段替换"的注入点是 load 递送还是 store data。
3. **K7 pattern 电池**(P4):orr/and/eor/add 的 op 偏置给了 pattern 激活面的首个梯度——固定 2×64b 跑全 0/全 1/随机/高汉明电池可直接映射损伤段的 pattern 敏感面。
4. **A 轨对照口径**:父版 rowmajor 三轮(223/244/276,自然随机数据)与 B 轨 87 的率差(2.6×)按预注册只报告率变化,不下"标签改变路径"结论——签名分布粗分类(可寻回/汉明/粒度)对比待跑 A 轨 dump 版本(父版无 dump,需 A' = 自然数据+dump 的第三格,或接受父版无签名仅有率的对照)。
