# CORE179 风扇降压热实验两次中止结果（2026-10-23 17:40 / 17:54）

**目的**：用户将风扇手动降至 60%（后又提至 80%），意图把 CPU4 推热（原定目标 70°C），跑 48-191 共 144 核（CPU1 已因空载 82°C 排除）neon_rot_ldr_at_top_rowmajor 15 分钟，配 98°C×2 看门狗。
**结果**：**两次均被看门狗中止——瓶颈是 CPU2，不是 CPU4。**

| | 60% 风扇（~11.6k RPM） | 80% 风扇（~15.6k RPM） |
|---|---|---|
| 负载窗 | 17:40:24-17:42:09（105s） | 17:54:51-17:56:48（117s） |
| CPU2 空载起跳 | 67°C | 63°C |
| CPU2 表现 | 10s 内 92°C，20s 起进入 PROCHOT 震荡 83↔103°C | 60s 到 93°C，110s 过 98/99°C（震荡幅度略小） |
| 看门狗触发 | 连续 102/103°C → 杀 | 连续 98/99°C → 杀 |
| **CPU4 峰值** | **70°C**（103s，瞬态） | **68°C**（114s，瞬态） |
| CPU4 形态 | 5s 内 50→60，60s 到 66-67，之后 ±5-9°C 震荡 | 同左，幅度略小 |
| SDC | 8 次/105s ≈ 4.6/min，全 179 | 13 次/117s ≈ 6.7/min，全 179 |
| 停机冷却 | 2min 回基线（CPU4→51，CPU2→70） | 2min 回基线（CPU4→49，CPU2→66） |

## 核心发现

1. **CPU2 是本机散热短板**：三插槽（CPU2/3/4）满载只有 ≈100% 风扇（自动策略）可持续（对照 16:06 自动风扇 168 核 30min 完整跑完，CPU2 稳态 74-77°C）。60% 和 80% 固定风速下 CPU2 分别在 20 秒 / 110 秒内越过 98°C。
2. **PROCHOT 震荡形态**：CPU2 温度 ±15°C、整机功耗 810↔650W、CPU4 跟随 ±5-9°C 同步摆动——时钟门控开→整机功率塌→各插槽回落→门控关→反弹。CPU2 温度传感器读数在 5s 采样间可摆 ±15°C（die 级响应）。
3. **CPU4 峰值几乎不依赖风速（70 vs 68）**：两次都被 CPU2 的节流循环封顶，从未到达自身稳态。CPU4 确实能摸到 70°C（用户原始问题），但只是节流波上的瞬态。
4. **空载温度随风扇变化**：60% → CPU1 空载 84°C（!）/CPU2 67/CPU3 56/CPU4 50-51，功耗 546-552W；80% → CPU1 73-75/CPU2 63/CPU3 55/CPU4 49，功耗 ~600W。
5. **SDC 再次与温度无正相关**：两次实验覆盖 CPU4 有史以来最猛烈的升温瞬态（5s 内 +11°C、100s 内 50→70°C、±9°C 震荡），触发率 4.6-6.7/min 反而低于 53-55°C 稳态的 15.4/min（16:06 实验）。21 次 fail 全锁 179。

## 结论与下一步

- 三插槽满载 + 降风扇的组合不可行（CPU2 先死）。
- **CPU4 热实验唯一干净配置 = CPU4-only 掩码（144-191）+ 降风扇**：无邻居抢热预算、无看门狗风险，CPU4 可到自身真稳态。
- 满载类实验必须带看门狗（本次两次保护均按设计生效，机器无损）。
