# CORE179 vmcore 内存 vs 寄存器 crash-probe（09-12 根因文档 §8.4 开口闭合）

日期: 2026-09-13 | 工具: crash + debug vmlinux + 2 份完整 vmcore

## 一、方法与发现

用 crash 直接读崩溃瞬间内存, 对照 Oops 寄存器值（此前 09-12 文档 §8.4 标注的
"证据链最后一块开口"——x20 读错值是从崩溃点推导的, 未直接观测）。

1. **运行时符号修正**: `__per_cpu_offset` 实际运行地址 = `ffffd431b37055d0`
   （09-12 文档写的 ffff800081f655d0 是 vmlinux 链接地址; 文档 §四的反汇编
   地址换算需按运行时偏移平移, 结论不受影响）。
2. **数组内存健康**（两份 dump 均验证）: 完美 0x22000 步进, 无任何垃圾 entry。
   - 09-12 10:00 dump: entry[20] = ffffabceccfb6000（正确值在内存里）
   - 09-11 14:31 dump: entry[179] = ffffa4bd92934000（x25=0xb3=179, 即 179 在读**自己的** offset）
3. **寄存器 x20 = 数组区域的错位字节窗, 非位翻转**:
   - 样本1 (09-12): x20=d74000ffffabcecc 与 base+19 处 8 字节**完全一致**
     （含 entry[3] 特异低位 d74000; 与正确值异或=32 位差异 → 排除 1-2 位翻转）
   - 样本2 (09-11): x20=9226e000ffffa4bd, 低 32 位=本 boot per-cpu 前缀
     ffffa4bd（=正确值的高 32 位, 错位视图）; x27=x1+x20 算术链逐位验证吻合
4. **结论**: 内存对, 寄存器错 → 损坏在 **CPU 179 侧的读路径**, 不在 DRAM/共享结构。
   与用户态 SDC 同签名（isolated-recross-golden: 内存 golden 正确, load 结果错）。
   §九的保留从"推导"升级为"实测"（caveat: 间歇性坏 cell 未被 2 样本完全排除,
   但两份 dump 数组均健康+寄存器含数组衍生数据, 读侧解释占优）。

## 二、28 份 dump 全量清点（修正 grep 模式后）

27/28 致命崩溃 = find_busiest_group+0x140 且 **CPU: 179**; 唯一例外 09-04 22:09
（CPU 50, list_debug 损坏, 同秒 CPU 180 亦有 WARNING, 179 同时命中——freeze 时代
的第二种"多核/写侧"损坏模式, 仅此一例）。

**"下线 179 后仍崩溃"核查**: 28 个崩溃 boot 内 179 在崩溃时刻**全部在线**
（正确模式: `psci: CPU179 killed` / `CPU179: Booted`）。其中 3 个 boot 曾下线过
179 但随后被重新上线, 崩溃发生在**回上线之后**:
- 09-08 17:21 boot: killed@1308s → re-online@61118s → 崩溃
- 09-12 00:09 boot: killed@6725s → re-online@7176s → 崩溃
- 09-12 10:00 boot: killed@190s/31720s → re-online → 崩溃@34999s
即本机三次"下线后仍崩"实为"下线→(战役需全核)回上线→崩"。

当前 boot (09-12 10:17 → 09-13 09:03, 23h): 179 四次下线/上线轮换 + 夜间在线空转,
零 panic。16:41 下线→16:42 回上线→17:26-17:48 发生 38 条 179 WARNING（pmdalinux）
——若下线者不知 16:42 的回上线, 会误判"下线无效"。

## 三、对他机/现场"下线后仍同栈 panic"的判据

find_busiest_group 在**每个核**的 newidle 路径执行——同栈不是 179 指纹, **CPU 行才是**。
- 对方 dump CPU 行仍=其坏核 → "下线"未生效（cpuset≠hotplug）或被回上线
- CPU 行散布多核 → 非 core 私有故障（共享 fabric/DRAM/软件）; 用本报告方法
  crash 读对方 __per_cpu_offset[]: 内存垃圾=写侧/共享; 内存健康=读侧(同本机病)
