## 五、温度轴定量核查（混淆排除）

各 run CPU4（179 所在插槽）全程平均：O3 臂 53.5 / 50.4 / 52.6，O0 臂 55.4 / 58.3 / 53.7 / 57.6 / 54.8——**O0 臂普遍热 2-3°C**。按温度专档已证梯度（每 +3.5°C 率减半），该温差最多解释 ~2× 率降，**无法解释 400→0 / 234→0 / 58→0 的归零**。

Poisson 论证：取最小 λ（movbe 58），O0 单项零检出概率 e⁻⁵⁸ ≈ 4.7×10⁻²⁶；五用例联合（λ 合计 ≥1072）P < 10⁻⁴⁰⁰。种子敏感性（auto seed）不构成解释——期望失败数是几十到几百对零。

## 六、次要观察（记录，不下结论）

1. **O0 臂迭代快 12-15%**（asm 热循环相同的前提下，外围编译产物拖慢了 O3 的每迭代耗时）——机制未知，objdump 后续。
2. **O3 臂 sub/str3 热稳态 >95°C**（各两次从 ≤70°C 冷启动仍在 ~2min 内冲过 95），O0 臂同用例仅 76-83°C——两臂功耗/吞吐差异，亦是编译产物行为差异的旁证。movbe-O3 从 ~93°C 热启动仍完成 30min（平台 84°C），58f 有效。
3. **冷却门 bug**：BMC 高频占用期（看门狗触发前后）`ipmitool` 定点读可能返回假小值致门误开（实测 31s 接续时 CPU2≈93）；隔离测试 cpu2() 正常（返回 97）。**未污染任何完整数据点**（仅让注定热死的重试提前启动）。修复方向：门控改用监控进程自己最后记录的采样值。
4. resume2 的 pass-2 重试会覆盖同 arm/test 日志（run4/8/redo 的块级明细丢失，计数保全于 summary.csv）。

## 七、按事前登记规则的判读（§二 规则 1 命中）

- **触发条件逐项满足**：O0 臂 5/5 全零（四法交叉）；O3 臂同晚全部正常 ≥1.93/min（完整跑 1.93-13.33，部分窗 3.8-8.85）。
- **判定（事前规则 1）：编译策略影响成立。**
- 规则 1 括号分支同时命中：**asm 热循环用例（rowmajor/sub/str3/mrn 四个）在 O0 下同样归零** → 触发窗并非仅由 asm 决定，**外围编译产物同样参与触发**——这本身即是新机制证据，H1'（asm 不变性）被否定，H1（时序窗破坏）在 movbe（纯 C++）上成立且扩展到 asm 用例。
- H0（两臂同量级）排除；规则 4（O3 整体异常低）未触发——O3 臂率在历史区间（rowmajor 13.3 ≈ 全扇凉端 13/min 档；movbe 1.93 ≈ 历史 1.9）。

**与既有知识的衔接**：历史结论"触发敏感到编译期寻址模式/指令调度级"（同 -O3 级内的布局敏感性）——本次把该结论从"同级布局"升级为"**-O 级别本身即是检出开关**"：同一晚、同一掩码、同一负载结构下，-O3 基线对 179 检出 1.9-13.3/min，-O0 构建五用例全部零检出。

## 八、局限与后续

1. **单跑/格子**：存在性级结论（归零 vs 百量级）由 Poisson 判死；率值精度与复现需多跑（用户纪律：单跑不下率结论——本判定仅为事前规则 1 的存在性判定）。
2. **归因残差**：O0 树与基线除 -O 级别外有既档差异（338 vs 368 TU，剔除非执行路径；Eigen 3.3.8 钉回一致；NDEBUG 一致，见设计文档 §3.4）。收窄到"纯 -O 级别"需对照：-O1/-O2 梯度，或在副本树以同 meson 参数重建 -O3。
3. **机制**：为何手写 asm 热循环的触发会被外围 -O0 破坏？候选（未证）：外围调度/对齐改变 asm 邻域时序、栈/帧布局与寄存器压力、无常量传播改变喂数组的寻址模式。 designated 后续：两二进制热循环邻域 objdump 对比。
4. **热**：O3 sub/str3 在本机（全扇 100%、全掩码）无法完成 30min——若需其完整率点，须更冷环境或分 socket 掩码（代价：破坏与本次其他点的可比性）。
