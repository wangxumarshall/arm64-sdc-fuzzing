# FARRON 在线 SDC 健康管理系统设计（v1.0，2026-10-25）

## 0. 总体状态机

## 0.1 双通道检测策略（2026-10-26 优化：日志预筛）

**被动通道（LogScanner，先于一切主动测试）**：SDC 故障核在内核侧往往留有指纹——本机实测验证：当前 boot 的 journal 中 **67 条 `WARNING: CPU: 179`（__do_kernel_fault，arch/arm64/mm/fault.c:494）100% 聚集于 179**，其余 191 核零条；与 9 月 panic 前兆链（52 条 spurious fault 全 179）同指纹族。

- **启动预筛**：全量扫描 → 达阈值（默认 3 条）核心携日志证据直送可疑队列，**免主动预筛**（本机上可零测试成本锁定 179）
- **持续增量**：周期 `--since 上次时间戳` 增扫；新告警爆发 = 异常事件（对应规格 3-1"应用报错"通道）
- 模式集：kernel_fault_warning / spurious_fault / kernel_oops / kernel_bug / hw_error；白名单滤除启动噪声（Booted secondary/GICv3/psci 等）；用户态崩溃行（segfault 等，无核号）计总量、触发全量扫描
- **诚实边界**：SDC 本质是静默的——本 boot 在 10-23 之前 179 已带病但日志零指纹（其损坏未踩中内核路径）。被动通道是加速器与先验，不能替代主动测试；主动通道（memcmp 类逐字节核对）才是兜底

**主动通道（PeriodicTester）**：捕捉日志不可见的静默损坏（本机 5h 评估 469 次 SDC 中仅 22 次同步泄漏为内核告警，其余 447 次纯用户态静默）。

## 2. 温度控制器（严格按规格）

- **采样**：每 `sample_interval`（默认 5s）读一次各插槽温度（`ipmitool sensor reading CPU*_TEMP`），维护长度 `W`（默认 12）的滑动窗口。
- **边界自适应**：当窗口内**超过一半**的温度记录已高于当前边界 `B`——说明应用正常工作温度本就偏高——**提高边界**（默认策略 `max`：`B ← max(窗口)`；可选 `step`：`B ← B + 2°C`），避免频繁降载。
- **触发降载**：**只有最新温度（window.tail()）超过当前边界**才启动降载（历史高不触发，只有当前高才触发）。
- **解除降载**：温度**回落至边界以下**（`window.tail() < B`）时解除。
- **降载动作**：暂停该插槽上的定期测试负载（本系统可控制的负载即测试本身），并落盘降载信号 `state/derate_<socket>.flag` 供用户应用侧配合。

## 3. 定期测试调度

- **选题优先级**：可疑级（本部署中已新发现错误的用例）> 活跃级（已证实检测器）> 基础级（从未触发的对照/未入账）。
- **与当前应用相关**：`config.app_tests` 可配置应用→用例映射；默认全池。
- **时长按温度边界动态分配**（热裕量 `margin = B - T_latest`）：

| 热裕量 | 分配时长 | 说明 |
|---|---|---|
| margin ≥ 10°C | 300s（基础时长） | 温度充裕，正常轮测 |
| 5 ≤ margin < 10°C | 120s | 压缩时长留热余量 |
| margin < 5°C | 60s 且只跑轻量用例（P3/P4） | 避免测试自身把温度推过边界 |
| 降载中 | 0（暂停该插槽） | 降温优先 |

## 4. 可疑级标记（在线状态发现新错误）

定期测试中某用例在**可靠池内的核**上出现 `result: fail`（新错误）：
1. 该用例针对该核标记为**可疑级**（`suspicious[core] += [testcase]`）；
2. 持久化更新 Testcase Pool（JSON 落盘）；
3. 该核进入**可疑状态**。

已知缺陷核（如本机 179）在初始标定时就排除在可靠池外，其常规触发不算"新错误"。

## 5. 可疑状态与裁决

1. **触发**：在线状态中某核在定期测试或应用运行中表现异常（测试失败 / 应用报错——应用侧通过 `state/anomaly_<core>` 文件上报）。
2. **深度测试**：从 Testcase Pool 取**针对该处理器（插槽）**的可疑级 + 活跃级用例，钉在该核上逐个深测（默认每用例 600s，活跃级按 P0→P1→P2…顺序，上限 `deep_test_cap` 个）。
3. **健康分析**：
   - 深测确认的缺陷核数（该插槽上累计）**< 2** → 仅屏蔽这些缺陷核（移出可靠池），插槽其余核心返回可靠资源池；
   - **≥ 2** → 整颗处理器退役（该插槽全部核心移出可靠池）。

## 温度灵敏度融入（v1.1，2026-10-30 三点改造）

**背景**：10-24/25 两战役确立 179 SDC 表达率与本座（CPU4）温度**单调负相关**——53°C ≈ 13/min（满率）vs 63.9°C ≈ 1.78/min，**每 +3.5°C 率减半**（校准源 `docs/CORE179_TEMPERATURE_RESEARCH_20261027.md`）。原 FARRON 温度逻辑全部为保护性（边界+降载）；本改造使其同时成为**灵敏度变量**。

### ① 温度补偿窗长（`temp_compensation_factor`）
- 定期轮与深测时长 = 热裕量基础时长 × **2^((T-53)/3.5)**（涉及插座取最热者）
- 低于锚点不缩短（52-53°C 为率平台）；因子上限 ×4（`temp_comp_max`），更热交给②
- 深测 gate 在 Farron 侧合成（降载=0 优先），`dur_cap = deep_test_duration × temp_comp_max`
- 假设注明：曲线在 CPU4/179 标定，推广全插槽为同硅假设；生产期可用 temp_5s.log + 各轮日志实证修正系数

### ② 凉检调度（cool scheduling）
- 定期轮：**热插座（>cool_threshold=55°C）的核本轮跳过**、只测凉插座、热插座等凉再覆盖——避免 CPU2 常态偏热拖垮全机检测可用性
- 全插座皆热：最长等 `cool_wait_max`（600s），超时带①补偿执行
- 深测：限时等待 `cool_wait_max_deep`（180s，更急）后带补偿执行

### ③ 检测轮风扇协同（`FanCoordinator`）
- 每个检测轮（定期/深测会话）前拉**全扇 100%**，轮后恢复原状态
- 依据：负关联的两候选机理（硅温度/风扇振动）在"全扇=最高表达率"上**同向**——无需等振动判别实验即可采用
- 凭据：环境变量 `BMC_HOST/BMC_USER/BMC_PASS` 或 `farron/bmc.env`（已 gitignore，模板 `bmc.env.example`）；未配置→自动跳过（不影响测试）
- 安全网：手动档带 `fan_revert_seconds`（3600s）自动回退——进程崩溃也回自动档；只升不降（避开降风红线）

### 附带加固
- **-O3 基线指纹钉死**（`check_binary`）：启动时核对 `builddir/opendcdiag` sha256 前缀（默认 `a05c17631da3e1a2`），不符拒绝启动——2026-10-30 发现编译产物是检出开关（-O0 构建五用例零检出）
- 单测试独占审计：RealRunner 每次调用单 `-e` 单测试串行 ✓（生产在线形态与应用共核为设计本意；实验期与 FARRON 互斥另见运行规约）

### 验证（2026-10-30）
- `--selftest` **17/17**（新增 5 项补偿因子断言：锚点 ×1.0 / +3.5°C ×2 / +7°C ×4 / 上限截断 / 平台不缩短）
- `--dry-run` 全弧线无回归：CPU4 过热→"热插座跳过，只测 144 凉核"；补偿 ×1.49@55°C；深测 891s（600×1.486）；风扇协同[dry] 每轮↑/恢复；新错误→可疑→深测确认→裁决

## 第二步调度

- **优先模式**（条件 2 ✓）：优先核所在 4 核组 ±1 组（= 周边核心，默认 [44±1]→核 172-183），每窗 **30s**（规格未给优先窗时长；取 10-25 实验的最小可靠窗——15s 窗单窗检出率仅 35%，30s 达 76-100%），每 30min 一轮，P0 用例轮换

## 两处必要修正（依据 10-25 三构型对照实验，CORE179_FARRON_PERF_VALIDATION_20261025.md §一）

1. **检测窗 = 组独占**：窗内核心先从应用整体迁出（taskset 全 worker 改亲和）再测——与应用共享（分时）构型实测零检出
2. **深测 = 整槽 48 核窗**：发现 fail 后的确认深测在整槽窗上跑、按 fail 块核归属裁决——单核钉核构型实测零检出（330s 零检出恰是 farron v1.0 deep_test 的构型，本修正即修它）
3. **n=4 共振属未测区**：n=1 独占=死、47+1 分时=死、n=48 整槽=活——4h 验收的优先窗本身即 n=4 共振测量；若 4h 零检出即"4 核组构型被负载门控关死"的直接证据（届时粒度下限需在 4-48 间标定）
